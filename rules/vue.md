# Vue 3

Самостоятельное правило для SFC. Те же принципы применяй к используемым из SFC composables/stores с учётом их контекста; сам glob не включает все `.ts` проекта.

- Для нового кода предпочитай Composition API и `<script setup lang="ts">`, сохраняя договорённости существующего проекта.
- `ref` читается через `.value` в script; template unwrapping имеет ограничения для вложенных refs и коллекций.
- Мутация принадлежащего компоненту `ref`/`reactive` допустима. Не теряй reactive-связь заменой объекта или извлечением примитивного snapshot.
- Vue 3.5+ поддерживает reactive destructure `defineProps` в том же `<script setup>`; для `watch` передавай getter. До 3.5 используй `props.x`/`toRefs` там, где нужна реактивность.
- `computed` getter — чистое вычисление. `watch` принимает ref/reactive/getter в зависимости от задачи; `watchEffect` отслеживает только синхронные чтения до первого `await`.
- Отменяй устаревшие запросы, снимай listeners/timers/subscriptions. Синхронно созданные setup-watchers останавливаются при unmount; отдельно созданным нужна явная очистка.
- Типизируй props/emits; родитель владеет входными данными. Не меняй props и вложенный объект родителя без явно согласованного контракта.
- Pinia не обязана иметь один стиль store. `storeToRefs` нужен для реактивного извлечения state/getters, но не actions; прямые state writes допустимы, бизнес-операции удобно группировать в actions.
- Для изменяемых списков используй стабильный identity key. Разделяй `v-if` и `v-for`, когда условие зависит от элемента.
- Не передавай недоверенный HTML в `v-html` без подходящей sanitization; проверяй недоверенные URL. Нативные labels, keyboard navigation и focus — часть контракта UI.
- При SSR не храни пользовательское состояние в module singleton и не обращайся к browser API во время server render. Не сериализуй секреты.
- Проверяй пользовательское поведение компонентов, loading/error/empty states и cleanup существующими средствами проекта. Оптимизируй после измерения, не по числу строк.
