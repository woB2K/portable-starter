# TypeScript

Применяется и к `<script lang="ts">` внутри `.vue`; это самостоятельное правило, без родительского набора.

- Следуй tsconfig, module system и форматированию проекта. Не ослабляй strictness для обхода ошибки.
- Внешний ввод принимай как `unknown`, затем валидируй и сужай тип. DTO/type assertion не выполняет runtime validation.
- Типизируй публичные контракты; очевидные локальные типы оставляй inference. `any`, `as` и `!` требуют реального основания, не подавления ошибки.
- Отделяй public DTO от ORM entities и секретных полей. Не выбирай единый response envelope без решения проекта.
- Обрабатывай rejected promises и ошибки парсинга на подходящей границе; не проглатывай исключения. Fire-and-forget требует явной стратегии ошибок.
- `forEach(async ...)` не ждёт завершения. Независимые операции параллельны только при допустимых нагрузке и failure semantics; зависимые — последовательны.
- Не доверяй пользовательскому URL, пути или SQL-фрагменту. Параметризуй запросы; allowlist для динамических идентификаторов.
- Не вводи запрет мутаций для Vue `ref`/`reactive`, Pinia или ORM-managed state: важны ownership, инварианты и отсутствие shared request state.
- В серверном request path избегай блокирующего I/O, неограниченного concurrency и непроверенных env; валидируй конфигурацию при старте.
- Проверяй изменения каноническими lint/typecheck/test командами проекта; typecheck должен охватывать `.vue`. Не подменяй их произвольным `tsc` по корню monorepo.
- Тесты выбирай по поведению: ошибки, null/empty, async races и границы доступа; не навязывай процент coverage или размер файла.
- При изменении зависимостей учитывай установленную версию API; не добавляй пакеты автоматически.
